# 旧多模式接口与引擎说明（归档摘录）

> 来源：迁移前 `README.md` / `docs/项目技术文档.md` / `docs/前后端接口JSON契约_v1.md`。
> 这些内容描述已下线的多模式能力，代码本体见 `archive/legacy_multi_mode/`。
> 恢复步骤见 [归档 README](../README.md)。

## 1. 引擎切换（`AGENT_ENGINE`）

- `core/facade.py` 按 `AGENT_ENGINE` 选择引擎，默认 `graph`（LangGraph 陪伴主图），`legacy` 可一键回滚到原 `ChatAgent`。
- 两者对外都暴露 `chat()` / `TurnResult`，server 无需感知差异。
- `.env` 可选变量：`AGENT_ENGINE=graph|legacy`。

## 2. 多模式配置（`mode_configs/`）

- 每个模式一份配置：系统提示词 / 工具白名单 / 模型生成参数，注册在 `agent/mode_configs/`。
- 内置模式：`emotion`（情感陪伴，默认）与 `office`（桌面办公）。
- graph 引擎当时固定为情感陪伴单模式，`set_mode` 仅保留接口兼容。

## 3. `GET /v1/modes`

返回模式注册表与当前进程级模式。

```json
{
  "current": "emotion",
  "modes": [
    { "name": "emotion", "display_name": "情感陪伴" },
    { "name": "office", "display_name": "桌面办公" }
  ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `current` | string | 进程级当前模式 |
| `modes[].name` | string | 模式标识，供 `/v1/chat` 的 `mode` 使用 |
| `modes[].display_name` | string | 展示名 |

## 4. `POST /v1/mode`

切换**进程级**当前模式；已存在的会话在下一次对话时惰性跟随。

请求体：

```json
{ "mode": "office" }
```

响应：

```json
{ "ok": true, "current": "office" }
```

错误：未知模式 → 400，`{"detail":{"code":"BAD_REQUEST","message":"未知的 agent 模式：xxx"}}`。

## 5. `POST /v1/chat` 的 `mode` 字段

```json
{
  "session_id": "default",
  "text": "今天北京天气怎么样？",
  "mode": null
}
```

`null` 表示使用进程当前模式；非 null 时本轮临时切到该模式。

## 6. legacy `ChatAgent` 工具循环

- `MAX_TOOL_STEPS` 限制工具循环轮数；工具通过 `ToolManager` 注册表白名单装配。
- 回复 JSON 由 `parse_reply_json` 解析出 `reply` / `emotion`，失败时回退原文与 `neutral`。
